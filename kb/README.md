# Knowledge base

Everything we learn and decide while building Pings. If it isn't written here, we didn't learn it.

```
design/vision.md        what Pings is for: goals (ranked), non-goals, strawman syntax, open questions
roadmap.md              phases: what we build, learn, read, and when each phase is done
decisions/              ADRs (architecture decision records), one per decision, numbered, never deleted
research/               study notes, one topic per file, in our own words, with sources
reading-list.md         books and papers by phase, with status
journal/YYYY-MM-DD.md   one entry per working session
glossary.md             terms, defined the first time we meet them
```

## Rules

1. **Own words.** Paraphrase; don't paste. Explaining it is how you find out whether you understood it.
2. **Cite sources.** Every research note lists what it's based on. Every ADR links the research behind it.
3. **Decisions are immutable.** ADR status goes Proposed → Accepted, or Rejected. To change an Accepted
   decision, write a new ADR that supersedes it; the old one stays as history.
4. **Journal every session**, even a short one. Future us will want to know why.
